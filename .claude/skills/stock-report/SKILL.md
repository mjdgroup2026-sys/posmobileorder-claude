# รายงานสถานะสต็อก (Stock Report)

สร้างรายงานสต็อกของโปรเจกต์ **posmobileorder** ในรูปแบบมาตรฐานเดียวกันทุกครั้ง เพื่อให้เทียบรายงาน
ข้ามวันได้

## ขั้นที่ 1 — ดึงข้อมูล

เลือกทางใดทางหนึ่ง **ตามสถานการณ์** อย่าเดาตัวเลขเองเด็ดขาด

**ทาง ก (ใช้เมื่ออยู่ในโค้ด/เขียนฟีเจอร์)** — เรียกฟังก์ชันที่มีอยู่แล้วใน `lib/queries.ts` ห้ามเขียน query ใหม่ซ้ำ:

| ฟังก์ชัน | ได้อะไร |
|---|---|
| `listProducts()` | สินค้าทั้งหมด พร้อมฟิลด์ `isLow` (คำนวณ `quantity <= reorderPoint` ให้แล้ว) |
| `getLowStockProducts(limit)` | เฉพาะรายการใกล้หมด เรียงตามความเร่งด่วน (`quantity - reorderPoint` น้อยสุดก่อน) |
| `getLowStockCount()` | จำนวนรายการใกล้หมด |
| `getDashboardStats()` | จำนวนสินค้าทั้งหมด + มูลค่าสต็อกรวม |

**ทาง ข (ใช้เมื่อต้องการดูข้อมูลสดจากฐานโดยตรง)** — query ผ่าน container

```bash
docker exec posmobileorder-postgres psql -U posmobileorderuser -d posmobileorderdb -c '
SELECT "sku", "name", "quantity", "reorderPoint", "unit"
FROM "product"
ORDER BY ("quantity" - "reorderPoint") ASC, "name" ASC;'
```

> ⚠️ ชื่อตารางใน raw SQL ต้องเป็น **`product`** (snake_case ตาม `@@map`) ไม่ใช่ `Product`
> ถ้า container ไม่ได้รัน (`docker ps` ไม่เห็น) ให้ `docker start posmobileorder-postgres` ก่อน
> **ถ้าดึงข้อมูลไม่ได้ ให้บอกตรง ๆ ว่าดึงไม่ได้เพราะอะไร ห้ามสร้างรายงานจากตัวเลขที่แต่งขึ้น**

## ขั้นที่ 2 — จัดสถานะแต่ละรายการ

ไล่ตามลำดับนี้ **ห้ามสลับลำดับ** เพราะสินค้าที่ `quantity == 0` เข้าเงื่อนไข `<= reorderPoint` ด้วยเสมอ
ถ้าเช็คผิดลำดับจะได้ป้าย "ใกล้หมด" ทั้งที่หมดไปแล้ว:

| ลำดับ | เงื่อนไข | สถานะที่แสดง |
|---|---|---|
| 1 | `quantity === 0` | `🔴 หมดแล้ว` |
| 2 | `quantity <= reorderPoint` | `⚠️ ใกล้หมด` |
| 3 | นอกนั้น | `✅ ปกติ` |

**เรียงลำดับแถว**: 🔴 หมดแล้ว → ⚠️ ใกล้หมด → ✅ ปกติ · ภายในกลุ่มเดียวกันเรียงตาม
`quantity - reorderPoint` จากน้อยไปมาก (เร่งด่วนที่สุดอยู่บนสุด)

## ขั้นที่ 3 — รูปแบบรายงาน (ต้องตรงตามนี้ทุกครั้ง)

```markdown
# รายงานสถานะสต็อก — <วันที่แบบไทย เช่น 31 สิงหาคม 2569>

| SKU | ชื่อสินค้า | คงเหลือ | จุดสั่งซื้อ | สถานะ |
|---|---|---:|---:|---|
| SKU-1003 | น้ำตาลทราย | 0 | 10 | 🔴 หมดแล้ว |
| SKU-1001 | ข้าวสาร 5 กก. | 8 | 10 | ⚠️ ใกล้หมด |
| SKU-1005 | น้ำมันพืช | 42 | 10 | ✅ ปกติ |

## สรุป

- **สินค้าทั้งหมด:** 7 รายการ
- **ต้องสั่งซื้อ:** 2 รายการ (🔴 หมดแล้ว 1 · ⚠️ ใกล้หมด 1)
- **ปกติ:** 5 รายการ
```

ข้อบังคับของรูปแบบ:

- **หัวข้อต้องมีวันที่เสมอ** ใช้วันที่ที่ดึงข้อมูลจริง ไม่ใช่วันที่ในตัวอย่าง
- คอลัมน์ตัวเลข (`คงเหลือ`, `จุดสั่งซื้อ`) จัดชิดขวาด้วย `|---:|`
- **ข้อความทั้งหมดเป็นภาษาไทย** (กติกาข้อ 6 ของโปรเจกต์)
- ถ้ามีสินค้าเกิน 30 รายการ ให้แสดงเฉพาะ 🔴 กับ ⚠️ ในตาราง แล้วเขียนใต้ตารางว่า
  "และรายการปกติอีก N รายการ (ไม่แสดง)" — อย่าทิ้งตารางยาวเป็นร้อยแถว
- ถ้าไม่มีรายการที่ต้องสั่งซื้อเลย ให้เขียนใต้สรุปว่า **"ไม่มีรายการที่ต้องสั่งซื้อ สต็อกอยู่ในเกณฑ์ปกติทั้งหมด"**
- "ต้องสั่งซื้อ" นับรวมทั้ง 🔴 และ ⚠️ เสมอ (ทั้งสองกลุ่มคือของที่ต้องเติม)

## กฎ

- **ห้ามใส่ semicolon (`;`) ในตัวอย่างโค้ดใด ๆ ที่เขียนในรายงานหรือคำอธิบาย** — กติกาข้อ 1 ของโปรเจกต์
  ใช้กับไฟล์ `.ts`/`.tsx` ทุกไฟล์ (คำสั่ง SQL ใน `psql` ที่ต้องมี `;` ปิดคำสั่งไม่นับ เพราะไม่ใช่ TypeScript)
- **ห้ามแก้ยอด `quantity` จากรายงานนี้** — รายงานเป็นงานอ่านอย่างเดียว ทุกการเปลี่ยนยอดต้องผ่าน
  `StockTransaction` ตามกติกาข้อ 2
- ถ้าผู้ใช้ขอให้ "สั่งซื้อ" หรือ "เติมสต็อก" ต่อจากรายงาน ให้ชี้ไปที่หน้า `/stock-in` หรือ Server Action
  `stockIn` **อย่าไปเขียน SQL อัปเดตยอดเอง**
